# Review archive: recorder, analysis and recordings

This archive accompanies the submission "An Empirical Study of High-Rate Motion Sensing with Apple
AirPods" and stands in for the software and data reference in the paper. It is anonymised for
review; the public release will carry a version tag.

## Contents

| Path | What it is |
|---|---|
| `MANIFEST.csv` | One row per recording: experiment, conditions, duration, samples, missing samples, loss, session losses, planned length, and whether the stream resumed after a session loss |
| `runs/<run-id>/` | The 79 recordings made over the accessory channel. Each has `samples.csv` (every report), `events.csv` (session events), `meta.json` (conditions, host, firmware) and `summary.json` (metrics as computed at recording time) |
| `runs/apple-api/` | The four baseline recordings through Apple's interface on the same Mac |

| `figures/` | The figures and the CSV behind each, as generated by `analysis/` |
| `tests/` | Unit tests of the metrics and the recorder's file handling |

The free-text notes in each `meta.json` were edited for release.

## Run names

`<date>-<time>_<experiment>_<requested rate>_r<repeat>`. Experiment codes: `E1` rate sweep not worn,
`E2` rate sweep worn, `E3` audio, `E4` distance and obstruction, `E5` 30-minute run, and `P` pilot
and exploratory recordings, which enter only the field-refresh analysis and the session-loss count.
The repeat number counts the recordings of one condition in the order they were made; the names
were assigned for this release. In `E2`, three runs lost their session and were repeated, which is
why some rates have a fourth repeat.

## The report and the two measures of loss

Each report on the channel is 56 bytes. `samples.csv` keeps it whole in `raw_hex`, next to the decoded
fields.

- **Sensor timestamp**: bytes 1 to 8, unsigned 64-bit little-endian, nanoseconds on the earbud's clock
  (`sensor_ns`). The origin is arbitrary; only differences are used.
- **Counter**: the last two bytes, unsigned 16-bit little-endian. It advances at 200 Hz whatever rate
  was requested, so its usual step per delivered report is 1, 2, 4 or 8 at 200, 100, 50 and 25 Hz. It
  wraps at 65,536; differences are taken modulo 65,536.
- **Host time**: `host_time` is the host's monotonic clock when the Bluetooth callback delivered the
  report. Reports delivered in one callback share it (`msg_idx`, `n_in_msg`).

Loss from timestamps (`metrics.sensor_metrics`): the sample period is the median step between
consecutive `sensor_ns`; each step is rounded to a whole number k of periods; k - 1 samples are
missing. Loss is missing / (received + missing). Loss from the counter (`metrics.counter_metrics`)
is computed the same way on counter steps. Both count what is missing between the first and the last received sample, so they do not see an outage at the end of a recording: where `session_losses` is not zero, compare `duration_s` with `planned_s` and see `stream_resumed`. Delivered rate is (received - 1) / (last - first time),
on each clock.

A session is opened by `library/podsense/session.py` (`_macos.py` on this host): it disconnects the
earbuds from the operating system's session, opens the L2CAP channel, performs the handshake in
`protocol.py`, and sends the setting message that names the sensor service and the interval in
microseconds. If no report arrives for 4 s the recorder asks for the stream again; if the earbuds
disconnect it opens a new session (`session_lost` in `events.csv`).

## Regenerating the tables and figures

Python 3.10 or later with numpy and matplotlib:

```sh
python -m venv .venv
.venv/bin/pip install numpy matplotlib pytest
.venv/bin/python analysis/reproduce.py     # rewrites figures/*.csv, *.pdf, *.png from runs/
.venv/bin/python -m pytest -q tests/test_metrics.py     # tests/test_recorder.py also needs PYTHONPATH=library
```

The analysis reads only `runs/`; it does not need the earbuds or the library. Recording needs macOS,
the earbuds and `pip install pyobjc-framework-IOBluetooth`:

```sh
PYTHONPATH=library python -m podmeasure record --exp E1 --rate 200 --seconds 60 --in-ear no --audio none --distance 0.5m
```
